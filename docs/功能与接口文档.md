## 一、模块业务概述

### 1.1 功能目标

一款「AI 旅行规划」微信小程序：用户输入**目的地城市 / 开始日期 / 天数 / 人数 / 预算 / 兴趣偏好 / 体力 / 交通方式 / 其他需求**，AI 结合真实口碑（小红书、B 站等）+ 本地知识库，自动生成「每日行程 + 地图路线」攻略；到景点后支持**语音导游**（识别景点 + AI 讲解 + 语音问答）。



### 1.2 使用场景

| 场景 | 说明 |
|------|------|
| 出行规划 | 出发前输入需求，AI 生成一份可落地、含坐标的每日行程攻略 |
| 现场游览 | 到景点后定位/拍照识别，AI 生成讲解词语音播报 |
| 途中提问 | 按住说话提问（门票、历史、美食），AI 语音回答，支持多轮追问 |
| 多人协作 | 分享行程给好友，扫码加入后共同编辑、AI 重排 |
| 打包行李 | AI 按行程生成行李清单，逐项勾选/增删改 |
| 分享传播 | 把攻略分享给好友/朋友圈，或生成小程序码让别人扫码直达 |



### 1.3 核心业务流程

```
登录 → 生成攻略 → 查看/分享攻略 → 语音导游
        │              │                │
    表单页输入     结果页/历史页      到景点识别→讲解/问答
```

### 1.4 个人主体限制（重要约束）

小程序为**个人主体**，以下能力受限，产品设计时需遵守：

| 限制 | 影响 | 当前方案 |
|------|------|---------|
| 无微信支付 | 做不了付费/会员/打赏 | 已排除 |
| 不能选「旅游」类目 | 只能选「工具-信息查询」 | 介绍文案按信息查询写 |
| 不能用微信同声传译插件 | 不能用微信 ASR/TTS | 改用百度智能云语音 |
| 订阅消息仅「**一次性**」 | 授权一次只能发一条 | 生成完成时发一条即消耗 |

## 二、系统架构与模块依赖

### 2.1 技术栈

| 层 | 技术 |
|----|------|
| 前端 | 微信小程序（原生，队友负责） |
| 后端 | Spring Boot 4.0.8（Java 17）+ MyBatis |
| 存储 | MySQL + Redis + Zilliz Cloud（托管 Milvus 向量库） |
| AI | DeepSeek（生成/Function Calling/流式）、硅基流动 embedding、通义千问 qwen-vl（识图） |
| 搜索/地图 | 博查搜索、腾讯地图 WebService |
| 语音 | 百度智能云（ASR/TTS） |
| 对象存储 | 阿里云 OSS（头像） |
| 微信 | 登录 code2session、订阅消息、小程序码 |



### 2.2 后端模块划分

```
com.study.travel_guide
├── controller/     # 接口层（Auth / Trip / Guide / Voice / User / Admin）
├── service/
│   ├── workflow/   # 攻略生成工作流（7 步编排）
│   ├── agent/      # 智能体（ReAct + Function Calling + 工具）
│   ├── rag/        # RAG（embedding / 向量存储 / 检索 / 摄入）
│   ├── guide/      # 语音导游（识别 / 讲解 / 问答 / 知识库 / 种子）
│   ├── voice/      # 百度 ASR/TTS
│   ├── wechat/     # 微信（access_token / 订阅消息 / 小程序码）
│   ├── qwen/       # 通义千问识图
│   ├── memory/     # 用户记忆
│   └── ...         # DeepSeek / 博查 / 腾讯地图 / OSS / Trip / Auth / User
├── mapper/         # MyBatis 数据访问
├── config/         # 配置（JWT 拦截、CORS、OSS、RestClient）
└── common/         # 通用（Result / BizException / JwtUtil / 全局异常）
```



### 2.3 核心数据流（攻略生成）

```
前端表单
  → TripController.generate/stream
  → TripWorkflowService（7 步）
      ├─ RAG 检索   ← Zilliz（向量库）
      ├─ Agent 工具 ← 博查 / RAG / 腾讯地图
      ├─ 生成攻略   ← DeepSeek
      ├─ 反思校验   ← DeepSeek
      ├─ 地理编码   ← 腾讯地图
      └─ 持久化     → MySQL / 摄入 → Zilliz
  → 前端 SSE 流式展示
```

## 五、功能详细说明

### 5.1 攻略生成（核心功能）

#### 5.1.1 7 步工作流

`TripWorkflowService.generate` / `generateStreaming`，编排如下：

```
输入：city / startDate / days / peopleCount / budget / preferences(枚举数组) / energyLevel / transportation(枚举数组) / extraRequirements
  │
  1. 输入校验        city 非空，days ∈ [1,15]
  2. RAG 检索        用户记忆 + 知识库（topK=3，按 city 过滤）
  3. Agent 搜集      联网搜索 + 知识库 + 地理编码（1-2 轮工具调用）
  3.5 天气与季节     和风天气查 3 天预报 + 按 startDate 算季节，注入 prompt
  4. 生成攻略        DeepSeek 按固定 JSON schema 生成（雨天避户外/改室内、按季节荐应季景观）
  5. 反思校验        检查路线顺路/预算/体力匹配，可开关（workflow.reflect）
  6. 地理编码 + 顺路优化  并发查坐标（lat/lng），再按坐标最近邻贪心重排每天景点顺序
  7. 持久化 + 摄入    存 MySQL；攻略文本再喂回向量库（越用越聪明）
  └─ 异步：发订阅消息（生成完成提醒）
```

**天气与季节（3.5 步）**：若填了 `startDate`，后端按月份判断季节（春/夏/秋/冬 + 应季提示），并调用和风天气查未来 3 天预报，把「第 N 天 小雨 15~25°C」写进生成 prompt，让 AI 把户外景点调整到晴天、雨天改室内、每天 note 加天气提示。**未填日期或天气查询失败 → 自动跳过，退化为普通生成**。

**降级策略**：
- RAG 检索失败 → 降级为「无知识库生成」，仅靠联网搜索 + 大模型
- 天气查询失败 → 跳过天气信息，仅保留季节推荐，不影响生成
- 反思校验失败 → 保留原攻略（`reflectAndRefine` catch 后返回原 guide）
- 地理编码失败（某个景点没查到坐标）→ 该景点缺 lat/lng，不影响其他
- 订阅消息发送失败 → 仅日志告警，不影响生成结果

#### 5.1.2 RAG（检索增强生成）

```
检索（RetrievalService.retrieve）：
  用户 query → embedding（bge-m3，1024 维）→ Zilliz 向量检索（COSINE，topK=3，按 city 过滤）

摄入（IngestionService.ingest）：
  攻略文本 → 按 500 字分块 → embedding → 写入 travel_guide 集合（带 city 元数据）
```

**关键点**：每次生成的攻略会「喂回」知识库，实现**越用越聪明**——同一城市再次生成时能检索到历史优质攻略。

#### 5.1.3 Agent（智能体）

`AgentService.run` 采用 **ReAct 循环**（推理 + 行动），最多 6 轮：

```
循环：
  → 调 DeepSeek（带 tools 定义）
  → 若模型返回 tool_calls：执行工具，把结果回填，继续循环
  → 若模型返回最终文本：结束，输出「行程素材汇总」
```

三个工具（`Tool` 接口 + `ToolRegistry` 自动注册）：

| 工具 | 名称 | 能力 |
|------|------|------|
| 联网搜索 | `search_web` | 博查搜索真实口碑（小红书/B 站等） |
| 知识库检索 | `search_kb` | 检索本地攻略知识库（可按城市过滤） |
| 地理编码 | `geocode` | 腾讯地图查景点经纬度 |

#### 5.1.4 流式输出（SSE）

`POST /api/trip/generate/stream` 返回 `text/event-stream`，事件：

| type | data | 说明 |
|------|------|------|
| `step` | 字符串 | 进度提示（「正在搜索：杭州 美食」） |
| `search` | `{source, content}` | 搜索/检索的中间结果（source：知识库/联网搜索/地理编码） |
| `token` | 字符串 | 攻略 JSON 生成中的文本片段 |
| `done` | `{tripId}` | 生成完成 |
| `error` | 字符串 | 出错信息 |



#### 5.1.5 用户记忆

`UserMemoryService.buildMemoryContext(userId, 5)` 读取用户最近 5 条行程，提取「去过的城市 / 偏好类型 / 常用体力档位」，注入生成 prompt，实现个性化推荐。

### 5.2 ai导游

#### 5.2.1 景点识别（定位优先 + 拍照兜底）

```
identify(lat, lng, image)：
  ① 有坐标 → 腾讯地图 nearby 搜 500 米内景点（category=旅游景点）→ 命中返回 {attraction, source:"location"}
  ② 无坐标/未命中 → qwen-vl 识图 → 返回 {attraction, source:"image"}
  ③ 都失败 → 抛「未能识别景点，请尝试拍照」
```

#### 5.2.2 讲解生成（RAG + 联网 + 大模型）

```
narrate(attraction)：
  RAG 检索（attraction_guide 集合，topK=3，按 attraction 过滤）
  + 博查联网搜索（"景点 历史 典故 简介"）
  → DeepSeek 生成 200-400 字口语化讲解词（结构：来历/背景 → 2-3 个看点 → 实用建议，禁止 markdown）
```

**降级**：知识库无命中（新景点）→ 仅靠联网搜索 + 大模型。

#### 5.2.3 语音问答（多轮对话 + 记忆）

```
chat(sessionId, question, attraction)：
  读 Redis 会话历史（最近 10 条）
  + RAG 检索 + 博查搜索
  → DeepSeek 生成 100-200 字回答
  → 写回 Redis（TTL 2h）
```

首次 `sessionId` 为空，后端生成 UUID 返回，前端保存复用。



#### 5.2.4 语音识别/合成（百度 ASR/TTS）

| 能力 | 接口 | 说明 |
|------|------|------|
| ASR | `/api/voice/asr` | base64 音频 → 文字（要求 wav/16000Hz/单声道） |
| TTS | `/api/voice/tts` | 文字 → base64 mp3 |

`POST /api/user/profile` 接收 base64 头像，上传 OSS，返回公网 URL。**部分更新**：昵称/头像各自有值才更新，避免清空已有字段。

### 5.5 行李清单（AI 打包助手）

每个行程一份行李清单。`POST /api/trip/{id}/packing/generate` 让 AI 结合**目的地 / 开始日期 / 天数 / 人数**生成 10-20 项初始清单（覆盖证件、电子、衣物、洗漱、药品、其他），用户逐项增删改、勾选（`checked` 是否已打包）。协作者也能一起维护。

### 5.6 多人协作（行程共编）

分享行程 → 好友加入协作 → 成员共同查看/编辑/重排。权限：编辑/查看对 owner+协作者开放，删除/分享管理/踢人仅 owner。同步为手动刷新。

**加入协作的两种方式**（口令为 16 位分享 token，见 `POST /api/trip/{id}/share`）：

| 方式 | 触发 | 说明 |
|------|------|------|
| 扫码加入 | 主人 `GET /api/trip/{id}/qrcode` 生成小程序码（scene=`token=xxx`），好友扫码 | 更「微信生态」，体验版即可扫 |
| 输入口令加入 | 主人展示 16 位口令，好友在小程序输入框粘贴 | 不依赖扫码/转发，演示最稳 |

**「输入口令加入」交互流程（前端）**：

1. 主人侧：调 `POST /api/trip/{id}/share`（或 `qrcode`）拿到 `token`，页面展示口令 + 复制按钮。
2. 好友侧：行程列表页「+ 加入行程」入口 → 弹出输入框粘贴 16 位口令。
3. 前端调 `POST /api/trip/join`（body `{ "token": "..." }`），成功返回 `data.tripId`。
4. 用 `tripId` 跳转 `GET /api/trip/{tripId}` 详情；刷新列表也能看到协作行程（后端已支持列表返回协作行程）。
5. `join` 幂等：owner 自己加入 / 重复加入均不报错。

**涉及接口**：`POST /api/trip/{id}/share`、`GET /api/trip/{id}/qrcode`、`POST /api/trip/join`、`GET /api/trip/{id}/collaborators`。

### 5.7 对话式行程重排

一句话指令（「下午下雨改成室内」「节奏慢一点」）让 AI 在现有行程上**局部调整**（dry-run 只算不存），确认后走 `PUT /api/trip/{id}/result` 落库。

### 5.8 天气与季节感知

生成攻略时按 `startDate` 算季节、调和风天气 3 天预报，让 AI 雨天避户外、按季节荐应季景观（未填日期或查询失败自动跳过）。

## 六、通用规范

### 6.1 统一返回体

```json
{ "code": 0, "message": "ok", "data": { } }
```

- `code = 0` 成功；非 0 失败
- 失败时 `data` 为 null

### 6.2 错误码

| code | 含义 | 触发场景 |
|------|------|---------|
| 401 | 未登录 / token 无效 | 无 token、token 过期/非法 |
| 400 | 参数错误 / 业务错误 | 城市为空、天数超范围、识别失败 |
| 404 | 不存在 | 行程/分享不存在 |
| 500 | 服务器内部错误 | 未知异常 |
| 502 | 第三方调用失败 | AI / 搜索 / 向量库 / 地图 / 语音 / 微信接口失败 |

### 6.3 鉴权

- 除「登录」和「公开分享」外，所有接口需带请求头 `Authorization: Bearer <token>`
- 公开接口：`POST /api/auth/login`、`GET /api/trip/public/{token}`

### 6.4 特殊返回格式

| 接口 | 返回格式 | 前端处理 |
|------|---------|---------|
| `/api/trip/generate/stream` | SSE（`text/event-stream`） | `enableChunked` + `onChunkReceived` |
| `/api/trip/{id}/qrcode` | JSON 内嵌 base64 PNG | `wx.base64ToArrayBuffer` 转临时文件 |
| `/api/voice/tts` | JSON 内嵌 base64 mp3 | 转临时文件 + `InnerAudioContext` 播放 |

### 6.5 字段约束速查

| 字段 | 约束 |
|------|------|
| `days` | 1–15 整数 |
| `energyLevel` | `easy` / `medium` / `hard` |
| 坐标 `lat`/`lng` | GCJ-02 坐标系（与腾讯地图、微信一致） |
| 录音 | wav、16000Hz、单声道 |
| 分享 token | 16 位（scene=`token=`+16=22 字符 < 微信 32 上限） |

#### POST /api/trip/generate/stream

**接口描述**：流式生成攻略（SSE）。请求体同上，返回 `text/event-stream`，事件格式见 [5.1.4](#514-流式输出sse)。

**SSE 原始数据格式**（每个 chunk 以 `data:` 开头，空行结束）：

```
data:{"type":"step","data":"开始规划"}
data:{"type":"search","data":{"source":"联网搜索","content":"搜到的内容全文…"}}
data:{"type":"token","data":"攻略 JSON 片段"}
data:{"type":"done","data":{"tripId":1}}
```

前端解析：去掉 `data:` 前缀 → `JSON.parse` → 读 `type` 字段分发处理（`step` / `search` / `token` / `done` / `error`）。

**前端接收方式**：`enableChunked: true` + `onChunkReceived` 逐块接收，`timeout: 600000`（与后端 SseEmitter 超时对齐）。

#### POST /api/trip/{id}/reorder-from

**接口描述**：从当前位置出发重排某天景点（最近邻），返回顺序 + 相邻点之间的腾讯路线距离/时长（步行）。用户到了城市后，前端 `wx.getLocation` 拿当前位置传进来，得到「先去哪、相距多远」的最优顺序。**仅返回临时视图，不修改行程**。

**请求体**

| 字段 | 类型 | 必传 | 说明 |
|------|------|------|------|
| lat | double | 是 | 当前纬度（GCJ-02） |
| lng | double | 是 | 当前经度（GCJ-02） |
| dayIndex | int | 否 | 第几天（从 0 开始，缺省 0） |

**成功响应**

```json
{
  "code": 0,
  "data": {
    "dayIndex": 0,
    "route": [
      { "name": "西湖", "lat": 30.24, "lng": 120.14, "distance": 1200, "duration": 900 },
      { "name": "雷峰塔", "lat": 30.23, "lng": 120.15, "distance": 2300, "duration": 1800 }
    ]
  }
}
```

**字段说明**：`route[i].distance` 为从上一个点（第一个是当前位置）到该景点的**步行路线距离**（米），`duration` 为步行时长（秒），路线规划失败时两者为 `null`。

**业务异常**：`400` 缺 lat/lng / 天数索引越界；`404` 行程不存在（非成员）。



#### POST /api/route/optimize

**接口描述**：地图多点路线规划。前端在地图上标注多个景点（含名称+坐标），后端按最近邻排序，返回最优游玩顺序 + 相邻点之间的腾讯步行距离/时长。与已有行程无关，纯「标记多个点 → 算路线」。

**请求体**

| 字段 | 类型 | 必传 | 说明 |
|------|------|------|------|
| points | array | 是 | 标注的景点数组，每项 `{name, lat, lng}` |

**成功响应**

```json
{
  "code": 0,
  "data": {
    "route": [
      { "name": "西湖", "lat": 30.24, "lng": 120.14, "distance": null, "duration": null },
      { "name": "雷峰塔", "lat": 30.23, "lng": 120.15, "distance": 2300, "duration": 1800 }
    ],
    "totalDistance": 2300,
    "totalDuration": 1800
  }
}
```

**字段说明**：`route` 按游玩顺序排列，第一个点 `distance/duration` 为 `null`（无起点段），后续点为其到上一个点的步行距离（米）/时长（秒）；`totalDistance`/`totalDuration` 为全程合计。路线规划失败时对应值为 `null`。

**业务异常**：`400` 未标注景点 / 景点缺坐标。

#### WS /ws/guide/call（视频通话式 AI 搭子）

**接口描述**：WebSocket 实时语音对话 + 摄像头截帧识别。前端持续上传 PCM 音频帧（后端转发百度流式 ASR）+ 视频帧（qwen-vl 识图），识别到整句后走 Agent（攻略记忆摘要 + 附近/天气工具）生成回答并 TTS 回传。搭子**绑定某份攻略**（start 传 tripId），能查行程/记账、推荐附近、查天气、多轮闲聊，但**只读不修改**。

**连接**：`wss://域名/ws/guide/call`，鉴权用 query 参数 `?token=<JWT>` 或请求头 `Authorization: Bearer <JWT>`。

**前端 → 后端**（JSON 文本帧）：

| type | 字段 | 说明 |
|------|------|------|
| start | tripId（必传）、sessionId/lat/lng（可选） | 绑定攻略；lat/lng 为当前位置（供附近推荐） |
| audio | data=base64 PCM | 实时音频帧（16kHz 单声道） |
| frame | data=base64 JPEG | 视频帧（前端 1fps 截帧） |
| stop | — | 结束通话 |

**后端 → 前端**（JSON 文本帧）：

| type | 字段 | 说明 |
|------|------|------|
| ready | sessionId | 就绪 |
| asr_partial | text | 识别中间结果 |
| asr_final | text | 一句识别完成 |
| attraction | name | 识别到景点 |
| tts | data=base64 mp3, text | AI 语音回答 |
| error | message | 错误 |

**搭子能力**：查行程（今天去哪、景点介绍、门票、时长、贴心提示）、查记账（总花费/分类/明细）、推荐附近好玩的（`search_nearby` 工具）、查天气（`get_weather` 工具）、多轮闲聊。只读，不提供修改工具。

**前端要点**：录音用 `wx.getRecorderManager`（format=PCM、sampleRate=16000、numberOfChannels=1、frameSize=3200），`onFrameRecorded` 拿 PCM 帧转 base64 发 `audio`；摄像头用 `<camera>` + `takePhoto` 每秒截 1 帧发 `frame`；收到 `tts` 用 `wx.createInnerAudioContext` 播放。

## 八、异常与降级策略

### 8.1 第三方失败处理原则

| 第三方 | 失败时行为 | 是否阻断主流程 |
|--------|-----------|--------------|
| DeepSeek | 抛 502 | 是（核心） |
| 博查搜索 | 降级：无联网素材，仅知识库+大模型 | 否 |
| 腾讯地图 | 降级：坐标缺失 / 识别降级拍照 | 否 |
| Zilliz + embedding | 降级：无知识库生成 | 否 |
| 通义千问 | 降级：识图失败→定位识别 | 否 |
| 百度语音 | 抛 502 | 语音功能阻断 |
| OSS | 降级：头像上传失败，保留旧头像 | 否 |
| 微信 | 各接口独立失败 | 登录阻断；订阅/二维码各自降级 |

### 8.2 关键降级链

```
景点识别：定位 → 拍照 → 报错
讲解生成：RAG → 联网搜索 → 大模型（RAG 无命中不阻断）
攻略生成：RAG 失败 → 仅 Agent 联网 + 大模型
反思校验：失败 → 保留原攻略
```

### 8.3 异常抛出约定

- 业务异常统一抛 `BizException(code, message)`，由 `GlobalExceptionHandler` 转成 `Result` 返回
- 第三方调用失败统一用 `502`，并在 message 里带第三方名称和 status，便于排查

## 九、联调注意事项

### 9.1 登录链路

1. 前端 `wx.login()` 拿 code（5 分钟有效）
2. 调 `/api/auth/login` 换 token，存本地 storage
3. 后续所有请求带 `Authorization: Bearer <token>`

### 9.2 流式接口

- `wx.request` 需 `enableChunked: true` + `onChunkReceived` 接收 SSE
- 收到 `done` 里的 `tripId` 后，调 `GET /api/trip/{id}` 拿最终完整结果

### 9.3 base64 处理

- 小程序码 PNG：`wx.base64ToArrayBuffer` → 写临时文件 → `<image>` 展示
- TTS mp3：同上，转临时文件后 `wx.createInnerAudioContext` 播放

### 9.4 录音参数

- `wx.getRecorderManager` 用 `format: 'wav'`、`sampleRate: 16000`、`numberOfChannels: 1`，否则百度 ASR 识别不准

### 9.5 坐标一致性

- 全程 GCJ-02（微信定位、腾讯地图 API、前端地图组件一致），**无需坐标转换**
- 前端 `wx.getLocation` 拿到的就是 GCJ-02，直接传后端

### 9.6 鉴权拦截

- 后端拦截器放行 `OPTIONS` 请求（预检），其余 `/api/**` 都要 token
- 公开接口：`/api/auth/login`、`/api/trip/public/**`

### 9.7 内容安全

- 后端用微信 `msg_sec_check` 检测用户输入文本，覆盖三处：**改昵称**、**生成攻略的「其他需求」**、**语音问答的提问**
- 违规（`risky`）→ 返回 `400 内容包含违规信息，请修改后重试`
- 疑似（`review`）→ 放行但记日志；接口异常 → 放行（内容安全不阻断核心流程）

### 9.8 数据库迁移（老库补列）

- `schema.sql` 的建表语句都带 `IF NOT EXISTS`，**对已存在的库不会自动加新列**。早期建的库需手动执行：

```sql
ALTER TABLE `user` ADD COLUMN points INT NOT NULL DEFAULT 0;
ALTER TABLE `user` ADD COLUMN growth INT NOT NULL DEFAULT 0;
ALTER TABLE `user` ADD COLUMN level INT NOT NULL DEFAULT 1;
ALTER TABLE `user` ADD COLUMN is_admin TINYINT(1) NOT NULL DEFAULT 0;
```

- 设置管理员：`UPDATE user SET is_admin = 1 WHERE id = <目标用户id>;`
- 新增的表（`trip_collaborator`、`packing_item`、`expense`）都是**新表**（不是加列），重新执行 `schema.sql` 即可创建（`CREATE TABLE IF NOT EXISTS`），无需 ALTER。
